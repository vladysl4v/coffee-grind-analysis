# Coffee Grind Fineness Dataset

## Contributing

> [!CAUTION]
> **NO DIRECT PUSHES TO `main` — EVER.**
> **NO SELF-MERGES — ALWAYS GET A REVIEW FIRST.(@vladysl4v)**
> **NO MERGE WITHOUT TEAM DISCUSSION.**

- PRs must be focused and reasonably scoped — one feature or fix per PR.
- **Keep branches short-lived** — merge back to `main` (or your epic) as soon as the work is stable. Long-lived feature branches cause painful merges.

> **Note:** The first 3 commits to `main` were initial project scaffolding and are the only exception to the rules above.

### Branch naming

| Type | Pattern | Example |
|------|---------|---------|
| New feature | `feature/<description>` | `feature/resnet-backbone` |
| Chore / tooling | `chore/<description>` | `chore/update-dependencies` |
| Bug fix | `fix/<description>` | `fix/csv-decimal-parsing` |
| Experiment | `experiment/<description>` | `experiment/augmentation-tuning` |
| Long-running epic | `epic/<description>` | `epic/model-a-exploration` |

Keep branches short-lived — merge back to `main` (or your epic) as soon as the work is stable.

### Workflow

1. Branch off `main`, do your work, push your branch.
2. Open a Pull Request and assign **@vladysl4v** as reviewer *(temporary — review ownership may be revisited as the project matures, but kept this way for now to maintain a consistent process)*.
3. Wait for approval — **do not merge your own PR**.
4. Reviewer merges into `main` after approval.

### Epics — long-running work

If your work will diverge significantly for an extended period (e.g. a model exploration running in parallel with the rest of the team), create an `epic/<description>` branch and treat it as your local `main`:

- Working **with others**: branch off the epic with `feature/`, `fix/` etc. and open PRs into it — same review rules apply.
- Working **alone**: you may commit directly to the epic branch.

When the epic is complete, open a single PR from the epic branch into `main`.

## Working with Data

### Directory structure

```
data/
  labels/
    labels_train2.csv             ← full labeled dataset (gitignored, obtain separately)
    train.csv                     ← fixed split (do not regenerate)
    val.csv
    test.csv
    augmented_raw_train.csv       ← generated by precompute_augmented_segmentation.py --raw-output
  images/
    raw/                          ← place raw images here (gitignored)
    synthetic/                    ← place synthetic images here (gitignored; .gitkeep tracked)
    augmented_raw/                ← augmented raw train images + original raw val/test (gitignored)
    rejected/                     ← images flagged as blurry/corrupted (gitignored)
  features/
    numerical/                    ← gitignored — generate locally (see step 7 below)
      train_features.csv          ← precomputed numerical descriptors for train split
      val_features.csv            ← precomputed numerical descriptors for val split
```

### First-time setup

1. Place `labels_train2.csv` in `data/labels/` (semicolon-delimited, `Sample;Fineness`).
2. Place raw images in `data/images/raw/`.
3. Generate train/val/test split CSVs:
```bash
uv run python src/split_labels.py --source raw
```
4. *(Optional)* Generate precomputed augmented training data (~3× dataset size by default):
```bash
# augmented raw images (all augmentations including photometric)
uv run python src/precompute_augmented_segmentation.py --raw-output

# custom multiplier
uv run python src/precompute_augmented_segmentation.py --raw-output --augmentations-per-image 5
```
5. *(Required for hybrid models)* Precompute numerical features. Output CSVs are gitignored — each team member must run this locally:
```bash
uv run python src/precompute_numerical_features.py
```
This writes `data/features/numerical/train_features.csv` and `val_features.csv`. Without these files, `numerical_features_plus_cnn` and `numerical_features_plus_efficientnet_b0` will fall back to on-the-fly computation (slow).

### Split rationale

> **Do not re-run `split_labels.py`.** The split CSVs (`train.csv`, `val.csv`, `test.csv`) were generated once and are fixed. Re-running would re-shuffle the split and invalidate comparisons between existing runs.

4 consecutive photos of the same grain share the same fineness value. Splitting per-image would leak the same grain across train/val/test. The split operates on **grain groups** instead, keeping all 4 photos of a grain in the same split.

| Split | Groups | Images |
|-------|--------|--------|
| Train | 115 (79%) | 489 |
| Val   | 15 (10%)  | 60  |
| Test  | 16 (11%)  | 58  |

607 images pass quality filtering (41 blurry images removed). Fixed seed `SEED = 42`.

## Training

### State-of-the-art model

**ConvNeXt-Small · 420 px crop · 1 500 synthetic images — Val MAE 2.31%**

To train:

```bash
uv run python src/train.py --model convnext_small --epochs 100 --lr 1e-3 \
  --unfreeze-after 15 --early-stop-patience 12 \
  --synthetic --synth-limit 1500 --crop 420
```

To evaluate the saved best model (`data/runs/convnext_small/run_069/best_model.pt`):

```bash
uv run python src/evaluate.py run_069 --crop 420
```

### Recommended settings

Based on the full experiment grid (see `TRAINING_PLAN.md` for all results), the following settings consistently outperform the defaults:

```bash
--adamw --cosine-lr --huber --huber-delta 0.03 --lr 3e-4 --epochs 100
```

Best-performing configurations across models:

```bash
# ConvNeXt-Small — unfreeze after 15 epochs, adversarial training
uv run python src/train.py --model convnext_small --unfreeze-after 15 \
  --adamw --cosine-lr --huber --huber-delta 0.03 --lr 3e-4 --epochs 100 \
  --adversarial --adv-epsilon 0.02 --adv-weight 0.4

# EfficientNet-B0 — unfreeze after 10 epochs, augmentation + adversarial
uv run python src/train.py --model efficientnet_b0 --unfreeze-after 10 \
  --adamw --cosine-lr --huber --huber-delta 0.03 --lr 3e-4 --epochs 100 \
  --online-augment --adversarial --adv-epsilon 0.02 --adv-weight 0.4

# ResNet-152 — unfreeze after 10 epochs, augmentation + adversarial
uv run python src/train.py --model resnet152 --unfreeze-after 10 \
  --adamw --cosine-lr --huber --huber-delta 0.03 --lr 3e-4 --epochs 100 \
  --online-augment --adversarial --adv-epsilon 0.02 --adv-weight 0.4

# Hybrid CNN + numerical features
uv run python src/train.py --model numerical_features_plus_cnn

# Hybrid EfficientNet-B0 + numerical features
uv run python src/train.py --model numerical_features_plus_efficientnet_b0 --unfreeze-after 10 \
  --adamw --cosine-lr --huber --huber-delta 0.03 --lr 3e-4 --epochs 100
```

### Arguments

| Argument | Default | Description |
|---|---|---|
| `--model` | required | `resnet18`, `resnet152`, `resnext50`, `efficientnet_b0`, `convnext_small`, `convnext_base`, `vit`, `vit_large`, `simple_cnn`, `numerical_features_plus_cnn`, `numerical_features_plus_efficientnet_b0` |
| `--epochs` | `50` | Number of training epochs |
| `--lr` | `1e-3` | Learning rate |
| `--batch-size` | `32` | Batch size |
| `--num-workers` | `4` | DataLoader worker processes |
| `--unfreeze` | off | Train with backbone fully unfrozen from epoch 1 |
| `--unfreeze-after N` | off | Freeze backbone for N epochs, then unfreeze backbone at lr/10 |
| `--online-augment` | off | Apply full augmentation pipeline live on raw images every epoch |
| `--adamw` | off | Use AdamW optimizer instead of Adam |
| `--cosine-lr` | off | Use cosine annealing scheduler instead of ReduceLROnPlateau |
| `--huber` | off | Use Huber loss instead of MSE |
| `--huber-delta` | `0.1` | Huber loss delta threshold |
| `--adversarial` | off | Enable FGSM adversarial training |
| `--adv-epsilon` | `0.01` | FGSM perturbation magnitude |
| `--adv-weight` | `0.5` | Weight of adversarial loss (clean loss weight = 1 - adv-weight) |
| `--early-stop-patience N` | `20` | Stop if val MAE doesn't improve for N epochs (`0` = disabled) |
| `--synthetic` | off | Mix synthetic images from `data/images/synthetic/` into training |
| `--synth-val-frac F` | `0.1` | Fraction of synthetic data held out for a separate synthetic val split |
| `--synth-limit N` | all | Cap the number of synthetic training images used |
| `--real-only-after-unfreeze` | off | Drop synthetic data from training when backbone unfreezes (requires `--unfreeze-after`) |
| `--crop N` | `224` | Centre-crop size in pixels |

When `--synthetic` is active, val metrics are reported separately for the real and synthetic splits, and `metrics.csv` gains `val_real_*` / `val_synth_*` columns. `data/labels/synthetic.csv` must exist (semicolon-delimited, `Sample;Fineness` header, fineness as a decimal value 0–100).

Artifacts (loss curves, scatter plots, checkpoints, `config.json`, `metrics.csv`) are saved to `data/runs/<model>/run_NNN/`.

### Running the full experiment grid

`run_all_experiments.py` runs every configuration from `TRAINING_PLAN.md` in memory-safe order (smallest models first), catches failures, and logs them to `failed_runs.log`.

```bash
uv run python run_all_experiments.py                # run everything
uv run python run_all_experiments.py --dry-run      # print commands without running
uv run python run_all_experiments.py --start-at 12  # resume from experiment 12
```

To rerun failed experiments (automatically uses `--batch-size 16` for commands that don't already specify one):

```bash
uv run python run_failed_experiments.py
```

## Evaluation

**Module:** `src/utils/evaluate.py`

Evaluates a saved ConvNeXt-Small model on the real val set. Prints Val MAE, RMSE, bias, std, p80, p95 and saves a scatter plot, error distribution chart, and predictions CSV to the run directory.

```bash
# evaluate the best model
uv run python src/utils/evaluate.py run_069 --crop 420

# evaluate multiple runs side by side
uv run python src/utils/evaluate.py run_025 run_069

# evaluate a specific checkpoint file directly
uv run python src/utils/evaluate.py data/runs/convnext_small/run_069/best_model.pt --crop 420
```

Pass a run name (`run_NNN`) and it resolves `data/runs/convnext_small/<run>/best_model.pt` automatically. Use `--crop` to match the crop size the model was trained with (default: 224).

```bash

uv run python src/utils/plot_conformal.py --model convnext_small --run run_069 --alpha 0.05  # 95% intervals
```

Computes per-channel mean and std over the training set (used to set normalisation constants in `data_loader.py`). Only needs re-running if the dataset changes.

```bash
uv run python src/utils/compute_dataset_stats.py
```

